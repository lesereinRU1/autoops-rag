# AutoOps RAG：8分钟面试演示脚本

## 演示前准备

在PowerShell执行：

```powershell
Set-Location D:\autoops-rag
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\start_background.ps1
```

浏览器保留两个标签页：项目页面`http://127.0.0.1:8000`和API文档`http://127.0.0.1:8000/docs`。不要现场重建索引。

主界面默认使用40001与报文地址为何相差1作为示例。`16#80C8`只在故障码查询中出现一次，不要让所有演示都围绕同一个报码。

## 0:00～1:00：说明数据规模

打开项目页面，说明当前入库3份官方PDF，共1785页，生成16969个切片。其中12035个是1861张表的行切片。页面中的数量从Qdrant读取，不是固定写在网页里的数字。

再打开`/health`，核对`indexed_chunks=16969`、`table_row_chunks=12035`和`structured_tables=1861`。强调原始PDF、解析结果、表格缓存、模型和向量库都在D盘。

## 1:00～3:00：说明表格索引方式

在页面选择`只检索`，输入：

```text
RD_MB_DATA_LEN 允许读取多少个寄存器？
```

预期证据中出现绿色结构化表格标签、页码938、表格ID和`chunk_id`，并显示`RD_MB_DATA_LEN=1 to 125`。

说明每张表同时保留页面正文和按行整理的数据。表格行的格式为`表名 + 表头=单元格值`，并保存表号、行号、页码和边界框。这样参数名、范围和单位不会在切块时分开，也可以根据页码回到原PDF检查。

第二个问题：

```text
MB_CLIENT 状态码 80C8 在协议错误表中表示什么？
```

预期Top结果是第945页或944页的表格行，说明服务器未在指定时间响应，并给出真实引用。

## 3:00～4:30：把召回链讲透

回答顺序：

1. Dense使用`BAAI/bge-small-zh-v1.5`找语义相近内容，Top30；
2. BM25对`80C8`、`MB_DATA_LEN`、型号等精确词更敏感，也取Top30；
3. RRF按`1/(60+rank)`融合两路排名，避免直接比较两种不可比的分数，保留Top20；
4. 轻量重排结合词项覆盖、短语命中和原始排序选Top5；
5. LangGraph做工具路由、证据门控、一次查询改写和引用校验。

打开`reports/gold_evaluation.json`：15题小规模回归集中Dense Recall@5为60%，BM25为93.33%，Hybrid为100%。不要把100%讲成生产准确率；这批题未经过独立盲审，10题来自项目补充资料。单看5道官方手册题，Hybrid MRR@10为56.67%、nDCG@10为67.50%，说明证据能进前5，但还没有稳定排在前两名。

再打开`reports/application_evaluation.json`。同一20题自查集上，事实字符串覆盖从36.67%升到96.67%，5道不可回答或危险请求的拒答率从0升到100%。明确说明字符串覆盖不是语义Answer Correctness，数据也没有独立盲审。中英文Query扩展实验曾使Recall下降，因此默认关闭，这是一次可以讲清楚的失败驱动取舍。

最后打开`reports/runtime_benchmark.json`。单并发P50为249.88毫秒；8并发P95为2406.08毫秒，吞吐量为4.668请求/秒。查询已经允许并发读，重建仍为独占写；本机CPU计算和SQLite写入是剩余限制。

## 4:30～5:30：解释向量库选型

打开`docs/ADR-001-vector-store-selection.md`。说明比较过FAISS、Chroma、Qdrant Local、pgvector和Milvus。当前是Windows单机、D盘持久化、约1.7万向量，还需要按型号、版本、页码和表格坐标过滤，所以选Qdrant Local。它不是性能上全面最优。超过单机原型规模、多副本或多用户写入时迁移到Qdrant Server。如果团队已有PostgreSQL，pgvector可能更合适。

顺带说明Local模式有单进程文件锁，所以服务运行时评测通过API，不会第二次直接打开索引。

## 5:30～7:00：演示工具选择和反馈记录

切回`手册问答`，输入：

```text
S7-1200 使用 MB_CLIENT 出现 16#80C8，应该按什么顺序排查？
```

回答后继续输入：

```text
这个故障先检查哪些地方？
```

页面应显示使用历史1轮。多轮记录保留24小时，可以点击`清空本页会话`删除。

依次指出：

- 路由到`lookup_alarm_code`；
- 知识关系中记录了MB_CLIENT可能出现16#80C8；
- 混合检索找手册证据；
- 回答带文档、页码和`chunk_id`；
- 程序校验引用是否真实存在；
- 运行统计显示总耗时、历史轮数、检索操作数和外部模型调用次数；
- 点击`有帮助`或`无帮助`可以记录反馈。只有人工点击`保存为已确认方案`后，方案才会保存，并用于后续相似问题。

不要声称已经降低MTTR或提高一次解决率：当前没有真实企业工单，业务指标为0才是诚实结果。

## 7:00～8:00：收尾与边界

收尾时说明项目包含资料版本记录、正文和表格索引、混合检索、工具选择、范围和安全门控、引用检查、用户反馈、应用层评测、限流和降级，不只是一个问答页面。

主动说明限制：检索回归集15题、应用层自查集20题，均未独立盲审；应用层官方手册题只有5道，多轮测试3组；经典S7-1200 V4.6待替换为V4.7；当前未接外部大模型，也没有企业工单和生产成效数据。

## 面试官追问时的短答

**为什么表格不只转Markdown？** 复杂PDF转Markdown时经常丢失跨列关系；行级键值表示更适合精确检索，完整正文表示保留上下文，两者同时入库。

**为什么Dense表现下降？** 语料扩展到大量相似参数表后，单纯语义相似容易召回同类但错误的行；BM25对型号、状态码和参数名更稳，RRF让两路互补。

**怎么避免旧索引污染？** 每个point ID由`chunk_id`确定；重建后滚动扫描Qdrant并删除不在当前`chunks.jsonl`中的points，`scripts/reconcile_index.py`会验证两边数量一致。

**为什么不是知识图谱RAG？** 图谱只用于领域实体解释和保守查询扩展，事实证据仍来自版本化手册。图谱扩展过宽曾在消融中降低Top5召回，所以限制在精确故障码场景。

**为什么没有上下文压缩？** 当前只为短追问加载最近1到2轮问题，不把完整聊天记录加入检索。以后增加长任务时，再保留设备型号、版本、已完成检查项和来源编号，压缩普通对话内容。

**KV cache怎么做？** 当前没有运行生成式大模型，BGE只负责计算向量，因此KV cache不适用。不能把embedding缓存说成KV cache。

**一次查询消耗多少？** `POST /api/chat`会返回总耗时、检索轮数、检索操作数、结构化查询次数和外部模型调用次数。当前外部模型调用为0，外部token为0。

**这是coding agent吗？** 不是。它只查询工业手册、故障码和参数，不编辑代码，也不执行PLC操作。项目重点是表格索引、混合检索、来源检查和资料版本管理。
