# 简历项目描述

> **Historical / stale / 历史版本材料。** 本文仍含旧 corpus/架构口径，不得直接作为当前简历文案；当前事实见 `docs/current-status.md`。

## 项目名称

AutoOps RAG - 工业设备手册检索与故障辅助系统

## 一句话功能

为S7-1200和Modbus技术手册开发本地检索程序，支持故障码、参数范围、普通问题和表格行查询，回答附带文档名称和页码。

## 问题背景

手册页数多，包含英文正文和大量参数表。只使用向量检索时，状态码和参数名容易召回到相似但错误的表格行；普通文本切分也容易把表头与数值分开。

## 主要工作

- 解析1785页官方资料并构建16969个切片，其中12035个表格行覆盖1861张表；保留型号、版本、页码、表头、行号、边界框和`chunk_id`，解决表头与参数值在普通切分中分离的问题。
- 实现BGE向量检索、BM25关键词检索、RRF合并和结果重排；建立带数据集SHA256、冻结锁、问题分类和失败记录的评测脚本。20题自查回归中保持Retrieval Recall@5为100%，将必要事实字符串覆盖从36.67%提升至96.67%，5道不可回答/危险题拒答率从0提升至100%。
- 使用LangGraph构建有界、可审计的RAG状态机，显式拆分请求分析、安全门控、工具执行、混合检索、证据门控、单次Query Rewrite、回答生成与引用校验节点；危险请求在检索和模型调用前短路，引用校验失败时强制降级为本地证据摘录。
- 拆分并发读与重建独占写，增加超时、限流、请求编号及OpenAI兼容接口的模型fallback与token统计；建立纯检索、本地摘录问答、外部LLM问答三种独立压测口径，分阶段记录检索、模型和编排P50/P95，定位CPU embedding与本地Qdrant瓶颈。

## 技术栈

Python / FastAPI / LangGraph / Qdrant / BGE / BM25 / RRF / PyMuPDF / SQLite / HTTPX / Pytest

## 口径限制

评测集仍以自建、自测数据为主，未经过独立盲审；事实字符串覆盖不是语义Answer Correctness。吞吐数字必须同时注明接口、生成模式、请求数和硬件环境，不能把本地摘录问答写成外部LLM端到端吞吐。项目没有企业内部工单和真实生产成效数据，不能据此声称已经在企业生产环境落地。
